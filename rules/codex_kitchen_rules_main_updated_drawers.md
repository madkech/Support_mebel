## 1. Общая цель расчета кухни

Программа должна рассчитывать кухню по цепочке:

```text
помещение → вопросы → кухня → модули → конструкция → детали → материалы → кромка → спецификация
```

Пользователь вводит размеры помещения и основные пожелания. Программа задает уточняющие вопросы, применяет правила по умолчанию, автоматически формирует кухню, рассчитывает детали и показывает результат. После этого пользователь может изменить любые параметры вручную, а программа должна пересчитать результат.

На текущем этапе визуализация не обязательна. Главная задача — правильная логика конструкции и расчет деталей.

## 2. Термины

### 2.1. Нижние столы

В пользовательском интерфейсе и текстах использовать термин:

```text
нижний стол
```

Не использовать как основной термин:

```text
нижняя тумба
```

В коде допустимы технические имена:

```text
base_table
lower_table
baseCabinet
```

Но пользователю показывать: **нижний стол**.

### 2.2. Навесные шкафы

Навесной шкаф — верхний кухонный шкаф.

### 2.3. Фартук

В этом документе `H_apron` означает расстояние от столешницы до низа навесного шкафа.

### 2.4. Бортик столешницы

Бортик — пристеночный бортик у столешницы.

## 3. Общие значения по умолчанию

```text
Материал корпуса: ЛДСП
Толщина ЛДСП по умолчанию: 16 мм
Толщина столешницы: 38 мм
Глубина столешницы: 600 мм
Высота ножек: 100 мм
Стандартная глубина корпуса нижнего стола: 510 мм
Стандартная глубина навесного шкафа: 300 мм
Стандартная высота навесного шкафа: рассчитывается по правилам высоты навесных шкафов; временное значение для ручного ввода / тестов — 720 мм
```

Все значения должны быть изменяемыми вручную.

## 4. Приоритет правил

Общий порядок применения правил:

```text
1. Ручной ввод пользователя.
2. Обязательные технические условия.
3. Условные правила.
4. Значения по умолчанию.
```

Примеры:

- если пользователь вручную указал высоту нижних столов 910 мм, использовать 910 мм;
- если есть Gola-профиль и посудомоечная машина, высота нижних столов 920 мм, если пользователь не указал другое;
- если есть микроволновка полного встраивания, глубина всех навесных шкафов 330 мм, если пользователь не указал другую глубину.

## 5. Нижние столы

### 5.1. Высота нижних столов

Высота нижних столов считается от пола до верха столешницы.

Базовые значения:

```text
Стандартная высота = 860 мм
Если есть Gola-профиль = 900 мм
Если есть Gola-профиль + посудомоечная машина = 920 мм
```

Приоритет:

```text
1. Ручная высота пользователя.
2. Gola-профиль + посудомоечная машина → 920 мм.
3. Только Gola-профиль → 900 мм.
4. Стандарт → 860 мм.
```

Формула высоты корпуса нижнего стола:

```text
H_base_carcass = H_base_total - H_countertop - H_legs
```

Где:

- `H_base_total` — высота нижней базы со столешницей;
- `H_countertop` — толщина столешницы;
- `H_legs` — высота ножек.

По умолчанию:

```text
H_countertop = 38 мм
H_legs = 100 мм
```

Примеры:

```text
860 - 38 - 100 = 722 мм
900 - 38 - 100 = 762 мм
920 - 38 - 100 = 782 мм
```

### 5.2. Дно нижнего стола

Актуальное правило:

```text
Дно нижнего стола по умолчанию наружное.
```

Это означает:

```text
Дно = W × D
Боковины = (H - T) × D
```

Где:

- `W` — ширина нижнего стола;
- `H` — высота корпуса нижнего стола;
- `D` — глубина корпуса;
- `T` — толщина ЛДСП.

Важно: старое правило `Дно = (W - 2T) × D` для обычного нижнего стола считать устаревшим.

### 5.3. Исключение: фасадная боковина

Если боковина нижнего стола планируется фасадной, то эта боковина становится наружной и идет на всю высоту корпуса.

#### Фасадная левая боковина

```text
Левая боковина = H × D
Правая боковина = (H - T) × D
Дно = (W - T) × D
```

#### Фасадная правая боковина

```text
Правая боковина = H × D
Левая боковина = (H - T) × D
Дно = (W - T) × D
```

#### Фасадные обе боковины

```text
Левая боковина = H × D
Правая боковина = H × D
Дно = (W - 2T) × D
```

### 5.4. Верхние планки нижнего стола

У обычного нижнего стола есть две верхние планки:

```text
передняя верхняя планка — 1 шт.
задняя верхняя планка — 1 шт.
```

Планки нужны для жесткости корпуса и крепления столешницы.

Планки всегда внутренние.

Размер планки:

```text
Длина = W - 2T
Глубина = 100 мм
```

Пример:

```text
W = 600 мм
T = 16 мм
Планка = 568 × 100 мм
```

#### Обычный нижний стол

Если в столе нет варочной панели:

```text
добавить 2 верхние планки
```

#### Варочная панель + духовой шкаф

Если есть варочная панель и духовой шкаф:

```text
верхние планки отсутствуют
```

#### Варочная панель без духового шкафа

Если есть варочная панель, но нет духового шкафа:

```text
планки есть, но опущены вниз на 100 мм
```

Размер остается:

```text
(W - 2T) × 100
```

#### Варочная панель без духовки, но с выкатными ящиками

Для текущего MVP:

```text
планки есть;
смещение 100 мм;
пользователь может изменить положение вручную.
```

Позже положение будет рассчитываться по высоте ящиков.

### 5.5. Полка нижнего стола

В нижнем столе может быть максимум одна полка.

Полка ставится только там, где это возможно.

Полка ставится:

```text
в обычный нижний стол с распашным фасадом, если пользователь не отключил ее вручную.
```

Полка не ставится:

```text
- в стол под мойку;
- в стол с выкатными ящиками;
- в стол под духовой шкаф;
- в стол под посудомоечную машину;
- в стол под встроенную технику;
- если пользователь отключил полку вручную.
```

Размер полки:

```text
Полка = (W - 2T) × D
Количество = 1
```


### 5.6. Нижние столы с выкатными ящиками

В нижних столах могут использоваться выкатные ящики.

Поддерживаемые типы систем:

```text
1. Шариковые направляющие.
2. Направляющие скрытого монтажа.
3. Tandembox / тандембоксы.
```

Если в нижнем столе есть выкатные ящики:

```text
- полка в этом столе не ставится;
- тип системы ящиков должен быть сохранен в данных;
- количество ящиков задается пользователем или правилом по умолчанию;
- фасад рассчитывается для каждого ящика;
- пользователь может изменить тип системы, количество ящиков и размеры вручную.
```

Для текущего этапа подробно фиксируется расчет ящиков на шариковых направляющих.

#### 5.6.1. Ящики на шариковых направляющих

Конструкция ящика:

```text
Боковины ящика всегда наружные.
Передняя и задняя стенка ящика устанавливаются между боковинами.
```

Обозначения:

```text
W_table = ширина нижнего стола
D_table = глубина нижнего стола
T = толщина ЛДСП
G = зазор под шариковые направляющие с одной стороны
D_drawer = глубина ящика
H_drawer = высота ящика
H_facade = высота фасада ящика
```

Зазор под шариковые направляющие:

```text
G = 13 мм с каждой стороны
Суммарный зазор = 26 мм
```

Ширина ящика считается по формуле:

```text
drawer_width = W_table - 2T - 26
```

Пример:

```text
600 - 32 - 26 = 542 мм
```

Так как боковины ящика наружные, передняя и задняя стенка ставятся между боковинами.

Формула ширины передней и задней стенки ящика:

```text
drawer_front_back_width = drawer_width - 2T
```

Или сразу:

```text
drawer_front_back_width = W_table - 4T - 26
```

Пример:

```text
600 - 32 - 26 - 32 = 510 мм
```

#### 5.6.2. Глубина ящика на шариковых направляющих

Если глубина нижнего стола `510 мм`, то:

```text
глубина ящика = 500 мм
длина шариковых направляющих = 500 мм
```

Для других глубин значение должно быть изменяемым вручную или рассчитываться отдельным правилом позже.

#### 5.6.3. Высота ящика на шариковых направляющих

Высота ящика определяется по высоте фасада.

Формула:

```text
drawer_height_raw = H_facade - 40 - 14
```

Или:

```text
drawer_height_raw = H_facade - 54
```

Высоту ящика нужно округлять в меньшую сторону.

Рекомендуемое правило для программы:

```text
drawer_height = floor(drawer_height_raw / 10) × 10
```

Пример:

```text
H_facade = 180 мм
drawer_height_raw = 180 - 40 - 14 = 126 мм
drawer_height = 120 мм
```

#### 5.6.4. Детали одного ящика на шариковых направляющих

Боковины ящика:

```text
количество = 2
размер = D_drawer × H_drawer
```

Передняя стенка ящика:

```text
количество = 1
размер = drawer_front_back_width × H_drawer
```

Задняя стенка ящика:

```text
количество = 1
размер = drawer_front_back_width × H_drawer
```

Дно ящика:

```text
материал = ХДФ 3 мм
количество = 1
ширина = drawer_width - 3 мм
глубина = D_drawer - 3 мм
```

Фурнитура:

```text
шариковые направляющие 500 мм = 1 комплект на ящик
```

#### 5.6.5. Пример расчета одного ящика

Входные данные:

```text
W_table = 600 мм
D_table = 510 мм
T = 16 мм
H_facade = 180 мм
```

Расчет:

```text
drawer_width = 600 - 32 - 26 = 542 мм
drawer_front_back_width = 542 - 32 = 510 мм
D_drawer = 500 мм
drawer_height_raw = 180 - 54 = 126 мм
drawer_height = 120 мм
```

Детали одного ящика:

```text
Боковина ящика = 500 × 120, 2 шт.
Передняя стенка ящика = 510 × 120, 1 шт.
Задняя стенка ящика = 510 × 120, 1 шт.
Дно ХДФ 3 мм = 539 × 497, 1 шт.
Шариковые направляющие 500 мм = 1 комплект
```

#### 5.6.6. Ящики на скрытом монтаже и Tandembox

Пока зафиксировать только тип системы и факт наличия ящиков.

Для направляющих скрытого монтажа и Tandembox точные формулы будут добавлены позже.

На текущем этапе для этих систем нужно:

```text
- сохранить тип системы;
- не добавлять полку;
- вывести предупреждение, что точный расчет выбранной системы будет добавлен позже;
- разрешить ручное изменение размеров.
```

## 6. Навесные шкафы

### 6.1. Базовая конструкция

Если нет специальных условий:

```text
Боковины идут на всю высоту шкафа.
Крышка ставится между боковинами.
Дно ставится между боковинами.
Полки ставятся между боковинами.
```

Обозначения:

```text
W = ширина шкафа
H = высота шкафа
D = глубина шкафа
T = толщина ЛДСП
```

Формулы:

```text
Боковина = H × D, 2 шт.
Крышка = (W - 2T) × D, 1 шт.
Дно = (W - 2T) × D, 1 шт.
Полка = (W - 2T) × D, количество по заданию
```

### 6.2. Если высота шкафа больше 850 мм

Если:

```text
H > 850 мм
```

то:

```text
Крышка идет во всю ширину шкафа.
Высота боковин уменьшается на толщину крышки.
```

Формулы:

```text
Крышка = W × D
Дно = (W - 2T) × D
Боковина = (H - T) × D, 2 шт.
```

### 6.3. Если есть врезная подсветка

Если планируется врезная подсветка:

```text
Дно идет во всю ширину шкафа.
Высота боковин уменьшается на толщину дна.
```

Формулы:

```text
Дно = W × D
Крышка = (W - 2T) × D, если нет другого условия
Боковина = (H - T) × D, 2 шт.
```

### 6.4. Если одновременно высота больше 850 мм и есть врезная подсветка

```text
Крышка = W × D
Дно = W × D
Боковина = (H - 2T) × D, 2 шт.
```

### 6.5. Универсальная формула боковины

```text
side_height = H - top_full_width * T - bottom_full_width * T
```

Где:

```text
top_full_width = 1, если крышка во всю ширину, иначе 0
bottom_full_width = 1, если дно во всю ширину, иначе 0
```

## 7. Глубина навесных шкафов

Стандартная глубина:

```text
300 мм
```

Если есть микроволновка полного встраивания:

```text
глубина всех навесных шкафов = 330 мм
```

Приоритет:

```text
1. Ручная глубина пользователя.
2. Если есть микроволновка полного встраивания → 330 мм для всех навесных шкафов.
3. В остальных случаях → 300 мм.
```

Важно: если в тестовом сценарии есть микроволновка полного встраивания, то все навесные шкафы должны рассчитываться с глубиной `D = 330 мм`, если пользователь не указал другую глубину вручную.

## 8. Высота навесных шкафов и добор к потолку

Высота навесных шкафов по умолчанию должна рассчитываться от высоты помещения, высоты нижних столов, высоты фартука и условий по потолку.

### 8.1. Новое понятие: добор к потолку

Добор к потолку — это верхний добор / технологическая зона между верхом навесных шкафов и потолком.

По умолчанию:

```text
H_ceiling_filler = 50 мм
```

Добор к потолку используется, если высота помещения уже указана с учетом готового натяжного потолка или если натяжной потолок планируется и программа рассчитывает кухню под будущий уровень потолка.

Пользователь может изменить размер добора вручную.

### 8.2. Вопросы программы по потолку

Программа должна спросить:

```text
Высота помещения указана с учетом натяжного потолка?
```

Варианты:

```text
1. Да, высота уже до готового натяжного потолка.
2. Нет, натяжного потолка сейчас нет.
```

Если пользователь ответил, что натяжного потолка сейчас нет, программа должна уточнить:

```text
Планируется ли натяжной потолок?
```

Варианты:

```text
1. Да, планируется.
2. Нет, не планируется.
```

### 8.3. Если высота уже с натяжным потолком

Если высота помещения указана уже до готового натяжного потолка, высота навесных шкафов считается так:

```text
H_wall_cabinet = H_room - H_base_total - H_apron - H_ceiling_filler
```

Где:

- `H_room` — высота помещения до готового потолка;
- `H_base_total` — высота нижних столов со столешницей с учетом правил;
- `H_apron` — расстояние от столешницы до низа навесных шкафов с учетом правил;
- `H_ceiling_filler` — добор к потолку, по умолчанию `50 мм`.

Пример:

```text
H_room = 2600 мм
H_base_total = 860 мм
H_apron = 600 мм
H_ceiling_filler = 50 мм

H_wall_cabinet = 2600 - 860 - 600 - 50 = 1090 мм
```

### 8.4. Если натяжного потолка нет, но он планируется

Если высота помещения указана до существующего потолка, но позже планируется натяжной потолок, программа должна заложить запас на натяжной потолок:

```text
H_stretch_ceiling_reserve = 80 мм
```

В этом случае расчетная высота будущего потолка:

```text
H_future_ceiling = H_room - H_stretch_ceiling_reserve
```

Высота навесных шкафов считается так:

```text
H_wall_cabinet = H_future_ceiling - H_base_total - H_apron - H_ceiling_filler
```

Или одной формулой:

```text
H_wall_cabinet = H_room - H_stretch_ceiling_reserve - H_base_total - H_apron - H_ceiling_filler
```

Пример:

```text
H_room = 2600 мм
H_stretch_ceiling_reserve = 80 мм
H_base_total = 860 мм
H_apron = 600 мм
H_ceiling_filler = 50 мм

H_wall_cabinet = 2600 - 80 - 860 - 600 - 50 = 1010 мм
```

Пользователь может изменить запас `80 мм` вручную.

### 8.5. Если натяжного потолка нет и он не планируется

Если натяжного потолка нет и он не планируется, расчет идет без добора к потолку. Вместо добора используется зазор до потолка:

```text
H_ceiling_gap = 40 мм
```

Формула:

```text
H_wall_cabinet = H_room - H_base_total - H_apron - H_ceiling_gap
```

Пример:

```text
H_room = 2600 мм
H_base_total = 860 мм
H_apron = 600 мм
H_ceiling_gap = 40 мм

H_wall_cabinet = 2600 - 860 - 600 - 40 = 1100 мм
```

Пользователь может изменить зазор `40 мм` вручную.

### 8.6. Приоритет расчета высоты навесных шкафов

```text
1. Если пользователь вручную указал высоту навесных шкафов — использовать ручное значение.
2. Если высота помещения указана с готовым натяжным потолком — использовать формулу с добором 50 мм.
3. Если натяжного потолка нет, но он планируется — вычесть запас 80 мм и использовать формулу с добором 50 мм.
4. Если натяжного потолка нет и он не планируется — использовать формулу с зазором 40 мм без добора.
```

### 8.7. Логика для CODEX

```ts
function resolveWallCabinetHeight(input: {
  manualWallCabinetHeightMm?: number;
  roomHeightMm: number;
  baseTotalHeightMm: number;
  apronHeightMm: number;
  roomHeightIncludesStretchCeiling?: boolean;
  stretchCeilingPlanned?: boolean;
  ceilingFillerMm?: number;
  stretchCeilingReserveMm?: number;
  ceilingGapMm?: number;
}): number {
  if (input.manualWallCabinetHeightMm) return input.manualWallCabinetHeightMm;

  const filler = input.ceilingFillerMm ?? 50;
  const stretchReserve = input.stretchCeilingReserveMm ?? 80;
  const ceilingGap = input.ceilingGapMm ?? 40;

  if (input.roomHeightIncludesStretchCeiling) {
    return input.roomHeightMm - input.baseTotalHeightMm - input.apronHeightMm - filler;
  }

  if (input.stretchCeilingPlanned) {
    return input.roomHeightMm - stretchReserve - input.baseTotalHeightMm - input.apronHeightMm - filler;
  }

  return input.roomHeightMm - input.baseTotalHeightMm - input.apronHeightMm - ceilingGap;
}
```

### 8.8. Ручное изменение

Пользователь может вручную изменить:

```text
- высоту навесных шкафов;
- размер добора к потолку;
- запас на натяжной потолок;
- зазор до потолка;
- высоту помещения;
- высоту нижних столов;
- высоту фартука.
```

## 26. Главное требование к коду

Код должен быть написан так, чтобы новые правила можно было добавлять постепенно без переписывания всей программы.

Желательно, чтобы каждое правило было отдельной функцией или отдельным объектом, например:

```text
resolveWallCabinetDepth()
resolveWallCabinetHeight()
resolveApronHeight()
resolveCountertopUpstand()
resolveHoodCabinetHeight()
resolveBaseTotalHeight()
resolveBaseTableRails()
shouldAddBaseTableShelf()
calculateWallCabinetParts()
calculateBaseTableParts()
calculateBallBearingDrawerParts()
applyManualOverrides()
```

Каждое правило должно возвращать не только результат, но и объяснение, почему оно применилось.

Пример:

```json
{
  "value": 330,
  "rule_id": "wall_depth_330_due_to_built_in_microwave",
  "message": "Глубина всех навесных шкафов установлена 330 мм, потому что есть микроволновка полного встраивания."
}
```
