# Главный документ для CODEX: ИИ-ассистент и база знаний мебельной программы

Дата версии: 2026-05-05
Статус: главный актуальный документ по архитектуре ИИ-ассистента

## Важно

Этот документ описывает архитектуру ИИ-ассистента, базы знаний и связи с расчетными модулями.

Правила расчета кухни находятся в отдельном главном документе:

```text
codex_kitchen_rules_main.md
```

Если нужно изменить мебельные правила, менять нужно документ правил кухни или соответствующие файлы базы знаний, а не только промпт ИИ-ассистента.

---

## 1. Цель ИИ-ассистента

В программе должен быть ИИ-ассистент, с которым пользователь общается обычным языком.

Ассистент должен помогать пользователю описывать кухню или другое мебельное изделие, задавать уточняющие вопросы, брать правила из базы знаний, формировать структурированные данные и передавать их в расчетный модуль.

Главная схема:

```text
Пользователь пишет обычным языком
        ↓
ИИ-ассистент понимает запрос
        ↓
ИИ-ассистент берет правила из базы знаний
        ↓
ИИ-ассистент задает недостающие вопросы
        ↓
Программа формирует структуру кухни / изделия
        ↓
Rule engine применяет правила
        ↓
Calculation engine считает детали
        ↓
ИИ-ассистент объясняет результат пользователю
```

Важно: ИИ-ассистент не должен хранить всю расчетную логику только внутри промпта. Правила должны храниться отдельно в базе знаний.

---

## 2. Общая архитектура

Программа должна быть разделена на логические части:

```text
/assistant
  отвечает за диалог с пользователем

/knowledge_base
  хранит правила, значения по умолчанию, формулы и условия

/rule_engine
  применяет правила из базы знаний к конкретной кухне или изделию

/calculation_engine
  рассчитывает детали, размеры, материалы, кромку и спецификацию

/output
  формирует понятный результат для пользователя
```

Главный принцип:

```text
ИИ-ассистент отвечает за понимание пользователя и диалог.
База знаний отвечает за правила.
Rule engine отвечает за применение правил.
Calculation engine отвечает за математику и размеры деталей.
Output отвечает за понятное отображение результата.
```

---

## 3. Что должен уметь ИИ-ассистент

ИИ-ассистент должен уметь:

```text
1. Принимать запрос пользователя обычным языком.
2. Определять тип задачи:
   - расчет кухни;
   - расчет навесных шкафов;
   - расчет нижних столов;
   - изменение уже рассчитанной кухни;
   - уточнение правил;
   - объяснение расчета.
3. Извлекать параметры из текста пользователя.
4. Понимать, каких данных не хватает.
5. Задавать уточняющие вопросы.
6. Использовать базу знаний для выбора правил по умолчанию.
7. Формировать структурированный объект кухни.
8. Передавать этот объект в rule_engine и calculation_engine.
9. Получать результат расчета.
10. Объяснять результат простым языком.
11. Предлагать пользователю изменить параметры вручную.
12. После изменений запускать пересчет.
```

---

## 4. Что не должен делать ИИ-ассистент

ИИ-ассистент не должен:

```text
1. Хранить все мебельные правила только в своем промпте.
2. Придумывать правила, если они уже должны быть в базе знаний.
3. Самостоятельно менять базу правил без явного действия пользователя.
4. Выполнять расчет деталей только текстом без структурированных данных.
5. Смешивать диалоговую логику, правила и расчеты в одном файле.
6. Перезаписывать ручные значения пользователя автоматическими правилами.
```

## 5. База знаний

На первом этапе база знаний может храниться в Markdown и JSON.

### 5.1. Человекочитаемые файлы

Markdown-файлы нужны для редактирования правил человеком:

```text
/knowledge_base/rules_md/kitchen_rules.md
/knowledge_base/rules_md/wall_cabinet_rules.md
/knowledge_base/rules_md/base_table_rules.md
/knowledge_base/rules_md/facade_rules.md
/knowledge_base/rules_md/countertop_rules.md
/knowledge_base/rules_md/apron_rules.md
/knowledge_base/rules_md/edge_rules.md
```

### 5.2. Машиночитаемые файлы

JSON-файлы нужны для работы программы:

```text
/knowledge_base/rules_json/kitchen_rules.json
/knowledge_base/rules_json/wall_cabinet_rules.json
/knowledge_base/rules_json/base_table_rules.json
/knowledge_base/rules_json/facade_rules.json
/knowledge_base/rules_json/countertop_rules.json
/knowledge_base/rules_json/apron_rules.json
/knowledge_base/rules_json/edge_rules.json
```

На первом этапе можно реализовать только JSON или локальные объекты в коде, но архитектуру нужно заложить так, чтобы потом можно было перейти к полноценной структурированной базе правил.

---

## 6. Пример структуры правила в JSON

Правило должно иметь понятную структуру:

```json
{
  "rule_id": "base_height_with_gola_and_dishwasher",
  "category": "base_tables",
  "description": "Высота нижних столов при Gola-профиле и посудомоечной машине",
  "condition": {
    "gola_profile": true,
    "dishwasher": true
  },
  "result": {
    "base_total_height_mm": 920
  },
  "priority": 30,
  "user_can_override": true
}
```

Еще пример:

```json
{
  "rule_id": "wall_cabinet_depth_with_builtin_microwave",
  "category": "wall_cabinets",
  "description": "Если есть микроволновка полного встраивания, глубина всех навесных шкафов 330 мм",
  "condition": {
    "has_builtin_microwave": true
  },
  "result": {
    "all_wall_cabinets_depth_mm": 330
  },
  "priority": 20,
  "user_can_override": true
}
```

Правило должно возвращать не только значение, но и объяснение для пользователя.

Пример:

```json
{
  "value": 330,
  "rule_id": "wall_depth_330_due_to_built_in_microwave",
  "message": "Глубина всех навесных шкафов установлена 330 мм, потому что есть микроволновка полного встраивания."
}
```

## 7. Приоритет правил

Общий порядок приоритетов:

```text
1. Ручной ввод пользователя.
2. Обязательные технические условия.
3. Условные правила.
4. Значения по умолчанию.
```

Примеры:

```text
- Если пользователь вручную указал высоту нижних столов 910 мм, использовать 910 мм.
- Если есть Gola-профиль и посудомоечная машина, высота нижних столов 920 мм, если пользователь не указал другое значение.
- Если есть микроволновка полного встраивания, глубина всех навесных шкафов 330 мм, если пользователь не указал другую глубину.
```

---

## 8. Диалоговый сценарий ассистента

Пример запроса пользователя:

```text
Хочу прямую кухню 2400 мм, газовая варочная, плитка клиента, нужна вытяжка, навесные шкафы 720 мм.
```

Ассистент должен извлечь:

```json
{
  "kitchen_type": "straight",
  "wall_length_mm": 2400,
  "cooktop_type": "gas",
  "apron_type": "client_tile",
  "has_hood": true,
  "wall_cabinet_height_mm": 720
}
```

Затем ассистент должен проверить недостающие данные и спросить, например:

```text
Нужна ли микроволновка полного встраивания в навесных шкафах?
Нужна ли врезная подсветка?
Планируется ли Gola-профиль?
Есть ли посудомоечная машина?
```

После ответов пользователя ассистент формирует полный объект кухни.

## 10. Rule engine

`rule_engine` должен:

```text
1. Получать объект кухни.
2. Загружать правила из базы знаний.
3. Применять правила по приоритету.
4. Учитывать manual_overrides.
5. Возвращать заполненный объект с рассчитанными параметрами.
6. Возвращать список примененных правил и объяснений.
```

Пример результата:

```json
{
  "base_total_height_mm": 860,
  "base_carcass_height_mm": 722,
  "wall_cabinet_depth_mm": 300,
  "apron_height_mm": 600,
  "countertop_upstand": false,
  "hood_cabinet_height_mm": 570,
  "rules_applied": [
    {
      "rule_id": "client_tile_apron_height_600",
      "message": "Для плитки клиента расстояние от столешницы до навесных шкафов 600 мм."
    }
  ]
}
```

---

## 11. Calculation engine

`calculation_engine` должен получать нормализованные параметры и считать детали.

Пример входа:

```json
{
  "module_type": "wall_cabinet",
  "width_mm": 600,
  "height_mm": 720,
  "depth_mm": 330,
  "material_thickness_mm": 16,
  "top_full_width": false,
  "bottom_full_width": true
}
```

Пример выхода:

```json
{
  "parts": [
    {
      "name": "Боковина",
      "qty": 2,
      "width_mm": 704,
      "height_mm": 330,
      "material": "ЛДСП 16 мм"
    },
    {
      "name": "Крышка",
      "qty": 1,
      "width_mm": 568,
      "height_mm": 330,
      "material": "ЛДСП 16 мм"
    },
    {
      "name": "Дно",
      "qty": 1,
      "width_mm": 600,
      "height_mm": 330,
      "material": "ЛДСП 16 мм"
    }
  ]
}
```

## 12. Assistant response layer

После расчета ассистент должен объяснять результат человеку.

Пример:

```text
Я рассчитал кухню по правилам по умолчанию.

Основные примененные правила:
- фартук клиента: расстояние от столешницы до шкафов 600 мм;
- газовая варочная: расстояние до вытяжки 750 мм;
- шкаф с вытяжкой: 720 + 600 - 750 = 570 мм;
- врезная подсветка: дно навесных шкафов идет во всю ширину;
- нижние столы: стандартная высота 860 мм.

Хотите изменить какие-то параметры вручную?
```

---

## 13. Изменения пользователя после расчета

Пользователь должен иметь возможность написать:

```text
Сделай нижние столы высотой 900 мм.
```

Ассистент должен:

```text
1. Понять, что это ручное изменение.
2. Добавить override.
3. Перезапустить rule_engine и calculation_engine.
4. Показать новый результат.
```

Пример override:

```json
{
  "target": "base_tables.base_total_height_mm",
  "value": 900,
  "reason": "manual_user_override"
}
```

---

## 14. Связь с главным документом правил кухни

ИИ-ассистент не должен сам решать, какие мебельные правила верные.

Правильная логика:

```text
1. Ассистент понимает запрос пользователя.
2. Ассистент формирует структурированные параметры.
3. Rule engine применяет правила из базы знаний.
4. Calculation engine считает детали.
5. Ассистент объясняет результат.
```

Если пользователь говорит:

```text
У меня будет Gola-профиль и посудомойка.
```

Ассистент должен передать в объект:

```json
{
  "gola_profile": true,
  "has_dishwasher": true
}
```

А rule_engine уже применит правило:

```text
Gola-профиль + посудомоечная машина → высота нижних столов 920 мм
```

## 15. Минимальная реализация для MVP

Для MVP нужно реализовать:

```text
1. Простую структуру базы знаний.
2. Загрузку правил из JSON или локального объекта.
3. Диалоговый слой, который формирует structured input.
4. Rule engine для применения текущих правил.
5. Calculation engine для навесных шкафов и нижних столов.
6. Сохранение ручных изменений пользователя.
7. Вывод результата в понятном виде.
```

---

## 16. Что пока не делать

На этом этапе не нужно делать:

```text
1. Полноценную 3D-визуализацию.
2. Сложный раскрой листов.
3. Оптимизацию остатков.
4. Полную коммерческую смету.
5. Интеграцию с реальными поставщиками.
6. Сложную базу пользователей.
7. Обучение собственной модели ИИ.
```

---

## 17. Главное требование

Все правила должны быть изменяемыми.

Нельзя жестко зашивать правило так, чтобы пользователь не мог его изменить.

Каждое правило должно поддерживать:

```json
{
  "user_can_override": true
}
```

Или аналогичный механизм ручного изменения.

---

## 18. Результат выполнения задачи

После выполнения задачи в проекте должна появиться основа архитектуры:

```text
ИИ-ассистент → база знаний → rule_engine → calculation_engine → результат
```

CODEX должен подготовить кодовую структуру, чтобы дальше можно было постепенно добавлять новые правила кухни, нижних столов, навесных шкафов, фасадов, столешниц и других мебельных изделий.
